## 这个功能解决什么

前两个功能假设「你就一个站」。实际上一台机器上散着好几个代码仓库：有的连着 GitHub，有的只是本地 git，有的远端换了地址。

同步页就是把它们统一管起来：**选一个本地目录，绑一个远端，拉取或推送**。

## 一、登记仓库

首次打开 Jarvis 时列表是空的。两种加法：

**扫描**——填一个根目录（默认 `~/Desktop/Code`），点扫描，会把 3 层以内的 git 仓库列出来，逐个点「添加」。

**手动**——直接粘贴绝对路径，比如 `/Users/you/Desktop/Code/my-project`。

> 只接受仓库根目录；子目录会被拒绝，并提示真实根在哪。

登记之后，顶栏的仓库按钮可以随时切换。配置存在 `jarvis/data/config.json`，删掉某个仓库只是从列表移除，**不会动磁盘文件**。

## 二、绑定远端

在「同步」页的输入框填 GitHub 地址：

```
https://github.com/用户名/仓库名
git@github.com:用户名/仓库名.git
```

`.git` 可以省略，https 地址会自动补全。用 SSH 地址的好处是不用配 token——只要本机 `ssh -T git@github.com` 能通。

保存后会立刻显示分支、领先/落后、以及 Actions 链接。

## 三、拉取与推送

| 按钮 | 实际命令 | 行为 |
| --- | --- | --- |
| 拉取 ← | `git fetch` + `git pull --ff-only` | 只做快进；有分叉或未提交改动就拒绝并报错 |
| 推送 → | `git push -u origin <branch>` | 建立上游跟踪；不带 `--force` |

**为什么拉取只做快进**：自动合并会悄悄生成合并提交，甚至留下冲突标记。工具宁可拒绝，也不替你做决定。

分叉了怎么办？到终端：

```bash
git pull --rebase origin main
# 解决冲突后
git push
```

## 四、状态怎么读

| 状态 | 含义 | 该做什么 |
| --- | --- | --- |
| 领先 N / 落后 0 | 本地有新提交 | 点推送 |
| 领先 0 / 落后 N | 远端有新提交 | 点拉取 |
| 两边都有 | 分叉 | 终端 rebase |
| 领先 0 / 落后 0 | 一致 | 不用管 |

> 如果本地分支名和远端默认分支不同（比如本地 `master`、远端 `main`），状态会标注「对比 origin/xxx」，推送会新建分支而不是覆盖。

## 五、边界

- 只操作 `origin`，不碰其他 remote。
- 拉取不做自动 stash；工作区有未提交改动时会失败。
- 不提供回滚、reset、rebase——那些留在终端。
- 所有 git 命令在对应仓库目录内执行，参数不经 shell 拼接。
